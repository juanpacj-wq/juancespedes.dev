story:
  hook: 'Quería que un asistente de IA hiciera mi trabajo en LinkedIn con mi propia sesión, sin guardar mi contraseña.'
  shifts:
    - before: 'Actualizar el perfil y postular, todo a mano.'

      after: 'El servidor escribe a través de la interfaz real, con la sesión de mi navegador.'
problem: La API oficial de LinkedIn no permite escribir en el perfil ni postular a ofertas, porque el acceso real exige un programa de socios y ni siquiera los socios pueden editar la experiencia. Quería que un asistente de IA hiciera ese trabajo con mi propia sesión, sin guardar mi contraseña y sin acciones sorpresa.
responsibilities:
  - Diseñé la separación entre lectura y escritura y el motor de formularios.
  - Implementé el servidor MCP, la CLI y el banco de respuestas reutilizables.
  - Lo publiqué con documentación de instalación y diagnóstico, y con herramientas para terminar a mano cualquier flujo.
constraints:
  - No hay API oficial para escribir; solo se puede a través de la interfaz.
  - La interfaz cambia de estructura y de clases CSS sin aviso, y se sirve en el idioma de la cuenta.
  - Ninguna acción visible para otras personas puede ocurrir sin confirmación explícita.
  - El inicio de sesión no se automatiza, porque dispara bloqueos y obligaría a guardar la contraseña.
decisions:
  - title: Leer por la API interna y escribir por la interfaz
    rationale: La API interna que usa la propia página devuelve el perfil y las ofertas estructurados en una sola llamada, con la sesión del mismo navegador. Para escribir no hay endpoint y se usa la interfaz. Si una de las dos vías falla, el servidor intenta con la otra.
    alternatives:
      - Raspar el HTML tanto para leer como para escribir
  - title: Campos identificados por su etiqueta visible
    rationale: El motor de formularios lee el nombre accesible de cada control y lo empareja con un glosario bilingüe. Funciona aunque cambie el HTML y con la cuenta en español o en inglés.
    alternatives:
      - Selectores por clases CSS
  - title: Un solo motor para el perfil y las postulaciones
    rationale: Editar una sección del perfil y completar una solicitud consisten en llenar un formulario. El mismo motor sirve para los dos casos, y una sección nueva no requiere cambios de código.
    alternatives:
      - Un flujo escrito a mano para cada formulario
  - title: Simulación por defecto y confirmación explícita
    rationale: Las acciones visibles para otras personas exigen confirmación, y las postulaciones corren primero en modo simulación para revisar las preguntas pendientes antes de enviar.
    alternatives:
      - Ejecutar directamente lo que pida el asistente

outcomes:
  - Un asistente puede actualizar el perfil completo, interactuar con otras personas y completar solicitudes con la sesión real del usuario.
  - Si un flujo falla, unas herramientas directas de navegador permiten terminarlo a mano.
  - El código es público, con documentación de instalación y diagnóstico.
lessons:
  - Pondría límites diarios conservadores y pausas entre acciones desde el primer día, porque las plataformas detectan patrones de automatización aunque la sesión sea real.
  - Agregaría pruebas con páginas reales guardadas para detectar los cambios de la interfaz antes de que fallen en uso.
